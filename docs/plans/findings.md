# findings.md — dsh-remote-workspace

## Ключевые выводы анализа dsh-remote
1. Преимущество 3-way sync: snapshot хешей предотвращает перезапись изменений при одновременном редактировании на сервере и локально.
2. Проблема 21 инструмента rw_*: перегружает LLM prompt. В новом плагине объединяем в 4 сбалансированных инструмента: 
emote_exec, 
emote_fs, 
emote_sync, 
emote_tunnel.
3. Модульность: вместо спагетти в index.js реализуем 4 отдельных Cordis сервиса.
4. UI: использование нативных CSS переменных DSH, чистый React, поддержка i18n (EN/RU/ZH).

## Результаты аудита стабильности и UI (Фаза 8)
1. **Баг localMirrorPath**: в форме профиля отсутствовало поле ввода localMirrorPath, что блокировало синхронизацию зеркала (400 Error).
2. **Баг рассинхронизации полей testConnection**: бэкенд отдавал latency/os, клиент ожидал latencyMs/
emoteOs.
3. **Утечка кэшированных SSH-соединений**: при смене хоста или ключа/пароля в профиле старое соединение с тем же id не сбрасывалось из пула SshService.
4. **Отсутствие UI для SSH-туннелей**: туннели были поддержаны на бэкенде, но не имели интерфейса в карточке настроек.
5. **Безопасность API**: отсутствовал фильтр isTrustedSettingsRequest(req) на мутирующих маршрутах.
